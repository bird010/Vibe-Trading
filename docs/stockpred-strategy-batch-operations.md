# StockPred 策略批次运维说明

## 两阶段流程

批次先执行海选：每个策略只写入摘要产物，不下载逐股票 OHLCV 详情。海选结束后批次阶段为 `screening_completed`，界面显示成功候选数、详情进度和空间估算提示。只有用户点击“生成前 20 名完整报告”才会调用详情物化接口；加载页面、轮询批次和 SSE 都不会自动物化。

默认按扣费后年化夏普排序，最多选择前 20 个成功海选报告。详情文件的实际空间取决于入选证券数和日期范围；海选摘要目录不含可选详情，并应保持在 20 个文件以内。

空间估算复用同一排序下前 20 个成功报告的 `detail_manifest` 代码数，并按 `DETAIL_ESTIMATED_BYTES_PER_CODE=2048` 字节/代码计算；它是 UI 预估值，不替代物化后的实际文件大小。

## 失败、停滞与恢复

详情失败只标记对应策略，已成功的详情不会重跑。运行中心跳过期的批次会在启动扫描时标记为 `stalled`，扫描只改状态、不执行海选或详情。再次发起详情请求会复用成功海选摘要；海选成功报告不会因恢复而重跑。

## 阶段指标与验收

每个策略运行目录的 `phase_metrics.json` 记录 `data_load`、`panel_build`、`factor_compute`、`execution`、`artifact_write` 耗时，以及读取行数、缓存命中/未命中、产物文件数和字节数。顶层指标只表示当前策略可归因的工作：因子计算、单策略执行和写入产物；共享读取和共享面板构建的顶层值为零。`batch_shared` 记录批次级、不可按策略累加的总量：`data_load` 仅包围 Lance 快照的实际读取，`panel_build` 仅包围缓存未命中的共享面板构建，`execution` 仅包围各策略最终执行，不包含面板或因子计算；缓存和读取行数也只在该对象中出现。

离线 `strategy_batch_benchmark.json` fixture 由十份真实海选工件的文件数与字节数聚合结果直接比较得出；它用于防止工件形状或大小的常量漂移，不以单机耗时百分比作为 CI 断言。

发布验收时，在同一机器和固定快照上确认海选总墙钟相对旧流程至少降低 50%，再评估详情物化最多 2 个 worker 的并发；当前实现不新增进程并发。
