# R81 代表基金选择与既有策略组合：研究设计

## 1. 研究目标

在不改变数据可见性、周频决策、交易执行和风险边界的前提下，评估 R81 的动态经济角色代表基金选择方式与既有策略信号或配置方法的组合，寻找可被滚动验证支持的综合策略。第一候选必须优先验证 R81 与 R58 的 R57 三因子信号组合；后续组合只有在机制上具有正交性、输入可用且不会引入不可审计的行为变化时才进入回测。

最终状态只能是 `FROZEN_RESEARCH_CANDIDATE` 或明确的未通过状态，不得据此自动部署、实盘交易或修改既有策略。

## 2. 第一性原理拆解

### 2.1 问题

R81 已经把“选哪个基金代表经济角色”与角色生命周期管理结合起来，但当前角色排序信号仍是持久化几何动量。需要判断：在代表基金已经由 R81 选择之后，替换或叠加一个已有策略信号，是否能提升风险调整后收益，并且不把代表选择、信号选择、组合配置和交易执行的收益来源混在一起。

### 2.2 基本事实

- R81 的核心机制是经济角色分类、动态代表选择、代表锁定/刷新/硬失败重选，并沿用 R34 分阶段再入场、R39 incumbent carry 和 R76 固定短债防御。
- R58 的核心信号是对当前候选代表使用严格因果的 R57 三因子：49 个交易日窗口、bias 0.3、slope 0.3、efficiency 0.4，至少两个完整候选，之后 Top3、等权和 R39 生命周期。
- 直接把 R58 的相关性聚类状态塞进 R81 会同时改变候选集合、状态机和代表定义，无法回答“R81 代表选择方式是否有效”。
- 历史 `f988e415122d` 批次含有 R80/R81/R76 的探索结果，但使用了确认区间且数据快照已变化，只能作背景证据，不能作本轮正式 OOS 或 Champion 证据。
- 默认 seed 运行身份 `e33b00bd5689` 在当前工作区及 `E:\code\stock` 可见范围内不可复现。该缺口必须写入实验台账，不能用旧批次静默替代。
- 当前 StockPred 数据可用：`fund.lance` v77、`fact_fund_adj.lance` v671、`dim_fund.lance` v62；当前快照指纹为 `7596807626fdf7f1aa9bdaddd84cd4575e15ac473c8331879d841ecacd941de6`，角色宇宙 1829 只，正常宇宙 1738 只。
- 当前快照的共同可用起点为 `2004-01-02`，但 R81 的固定短债 `511010.SH` 上市日为 `2013-03-25`；若从更早日期运行，R81 会在执行合同处失败。正式评估因此从 `2013-03-29` 开始至 `2022-07-29`，默认 Train156 / Validation52 / Test52 / Step52 可形成 5 个完整滚动折叠，仍满足至少三折要求；更早数据只用于预热和可用性审计。

### 2.3 不可变约束

- 所有比较共享同一个冻结快照、宇宙、周频日历、回测区间、执行合同和随机种子 `e33b00bd5689`；找不到 seed 只允许记录缺口，不得伪造或换成其他 seed。
- 正式研究区间止于 `2022-07-29`，不得使用已消费确认区间 `2022-08-01..2026-08-01` 的收益或折叠选择信息。
- 交易默认合同固定为初始资金 100 万、佣金 0.00025 且最低 5、其他费率 0、参与率上限 0.05、ADV 回看 20 日且至少 10 个观测、滑点 5–30 bps、整手 100；不得在候选策略之间调参。
- 每一轮只允许一个明确假设，Champion 与 Challenger 恰好两个变体；同一假设失败后不得以换名方式重复提交。
- 新策略必须使用独立策略 ID、独立包和独立实现哈希，禁止修改 R81、R58、公共 Runner 或执行合同来制造对照结果。
- 所有信号必须使用决策时点可见的收盘价、复权因子和元数据；缺失、非正、非有限或不满足最小样本时必须 fail closed。
- 研究结果只可晋级为研究候选，不得自动部署。

## 3. 正式比较口径

### 3.1 轮次和基线桥接

先建立一个不可晋级的 `seed_repro_probe`，尝试在当前快照重建默认 `correlation_representative` 身份；其目的只是验证默认 seed 缺口是否能被当前代码和数据解释。若身份仍无法还原，台账标记 `SEED_UNREPRODUCIBLE`，不把该探针当作正式 Champion。

随后建立 `R81_ANCHOR`：在同一当前快照、同一正式研究区间和同一滚动折叠下重跑 R81，作为本次用户指定问题的行为基线。该桥接基线不是对旧 `f988` 结果的复用。

正式轮次仍保存 `round_00` 的默认 seed 探针结果，并从 `round_01` 开始以 R81 anchor 作为初始 Champion，第一 Challenger 为 R82。这样既保留方法规定的 seed 审计轨迹，也避免把不可复现的旧身份冒充为 R81 组合研究的基准。

### 3.2 第一候选：R82

策略 ID：`ai_rotation_r82_economic_role_dynamic_rep_r57_signal`。

唯一主假设：在 R81 已完成经济角色代表选择后，以 R57 三因子替换 R81 当前的角色排序信号；不让 R57 反向选择角色内代表。

固定行为边界：

1. 保留 R81 的角色分类、动态代表选择、tier → ADV → code 的确定性排序、26 周刷新、代表锁定、硬失败重选和 PIT 检查。
2. 对每个当前角色代表，以截至信号日的 49 个交易日数据计算 R57 bias/slope/efficiency，权重固定为 0.3/0.3/0.4，完整候选至少 2 个。
3. 在角色层面对得分排序，选择 Top3 角色、每个角色 1/3；角色到代表的映射必须可审计。
4. 保留 R81 的 R34 分阶段再入场、R39 incumbent carry 和 R76 固定短债防御，以保证第一轮只改变信号层。
5. 因 R82 是经济角色状态，不生成或伪造 `cluster_id`；输出角色、代表、因子分数和 fail-closed 原因即可。

R82 不是 R58 的重跑，也不继承 R58 的相关性聚类状态机。R58 的 Top3、等权和 R39 只作为行为对照；R81 的代表选择是本假设的不可变上游。

### 3.3 后续候选排序

只有 R82 完成一轮完整审计并达到晋级门槛后，才按下列顺序设计后续单变量组合；每个候选都要先写独立假设，再实施和回测：

| 优先级 | 候选方向 | 改变的层 | 进入条件 | 明确排除 |
| --- | --- | --- | --- | --- |
| 1 | R81 动态代表 + R57 三因子（R82） | 信号层 | 当前优先项，先完成 | 不改代表选择和状态机 |
| 2 | R81 动态代表 + 防御相对动量（R77 方向） | 防御/覆盖层 | R77 输入从 `UNAVAILABLE_INPUTS` 变为可验证；否则只记未可用 | 不把不可用输入硬接入 |
| 3 | R81 动态代表 + 真逆波动率权重（R62 方向） | 组合权重层 | 选中代表集合、总暴露和生命周期保持不变 | 不同时改变信号和暴露 |
| 4 | R81 动态代表 + 角色级波动调整排序（R74 方向） | 信号排序层 | 明确角色级映射并通过因果测试 | 不直接复用 R74 的相关性聚类实现 |
| 5 | R81 动态代表 + 总组合波动目标（R75 方向） | 风险预算层 | 前述候选穷尽或已形成稳定 Champion | 不与逆波动率在同一轮叠加 |

R58/R59/R60/R72/R61/R73 等同源价格动量或重复相关性结构，不作为 R82 后的默认组合；R64/R66 属于计算/架构替代，不是可比较的策略增益；R76 已经是 R81 的下游防御组成；R80 是固定代表控制组；R71 仍处在代表层，直接叠加会混淆代表选择效果。若所有可用候选均未通过，剩余轮次必须记录 `NO_JUSTIFIED_HYPOTHESIS`，不得为了填满轮次而过拟合。

## 4. 回测和晋级规则

### 4.1 折叠

正式研究数据覆盖 `2013-03-29..2022-07-29`，采用连续账户运行并按 5 个滚动折叠切分指标：Train156 / Validation52 / Test52 / Step52。底层预热数据仍从当前快照的可用历史加载；Train 和 Validation 只用于研究记录与门槛判断，Test 结果只在折叠完成后汇总；不得按折叠挑选最优参数。若运行服务要求更短评估区间，必须保留完整预热数据并在 manifest 中记录裁剪规则。

### 4.2 Champion 门槛

以聚合 validation 指标为主：Challenger 的 Sharpe 必须更高，年化收益不得更低，MDD 不得恶化超过 1 个百分点；至少过半折叠胜出，且所有数据完整性、因果性、身份和执行门槛通过。Test 只用于最终审计，不得回写策略或选择规则。任何一项失败都不晋级。

### 4.3 必须验证的行为

- R81 与 R82 在代表选择、切换时间、角色宇宙和 PIT 结果上保持一致。
- R57 公式、49 日窗口、最小完整候选、缺失数据 fail closed，以及未来行不影响过去分数。
- 代表硬失败后必须使用新代表在同一信号日重新评分，不能沿用旧代表分数。
- Top3 角色到代表的映射、1/3 权重、现金、分阶段再入场、incumbent carry 和短债防御保持可审计。
- R82 的策略 ID、source snapshot、implementation hash、run identity 与 R81/R58 独立；批次报告严格 JSON，状态必须为终态并校验 Champion/Challenger 身份。
- 执行完成率、父单成交率、阻塞率、换手率和容量约束必须与收益指标一起报告；不得只按名义净值排名。

## 5. 产物和审计台账

实验目录需包含：冻结的 `experiment_spec.json`、数据/宇宙/折叠 `fold_manifest.json`、每轮 `request.json`、批次 `resolved_batch.json`、终态 `reports.json`、逐轮指标、append-only ledger、当前 champion 指针、review package、设计/实现/复核报告以及最终 `FROZEN_RESEARCH_CANDIDATE` 状态。所有中文说明文档采用中文；机器可读字段保持既有 API schema 和策略 ID 规范。

每轮都必须记录：假设、变更层、不可变项、输入可用性、批次幂等键、快照指纹、框架/执行哈希、折叠指标、门槛判定、review 结果和下一轮理由。不得删除失败轮次或覆盖历史 ledger。

## 6. 成功标准

只有同时满足以下条件才可声称找到更优综合策略：

1. R82 或其经逐轮晋级的后继候选，在冻结快照的正式滚动验证中满足 Champion 门槛；
2. 改善不是由确认区间泄漏、不同快照、不同执行合同、重复调参或身份串线造成；
3. 所有报告和逐轮台账可由另一位审阅者从批次原始产物重建；
4. 最终状态明确为 `FROZEN_RESEARCH_CANDIDATE`，并保留至少 104 周 forward-shadow 计划，不能标记为已部署。
