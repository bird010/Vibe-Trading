# StockPred 统一策略回测与 Alpha Zoo 批次比较设计

## 目标

让 StockPred 在不再只支持 Graph 的前提下，支持 Alpha Zoo 的全部已注册因子按需多选或全选回测。每个策略产生一份独立、可审计、可追溯的报告；同一批次中的报告在相同数据与执行条件下横向比较，并默认按扣费后年化夏普比率排序。

## 范围

- 统一 Graph 与 Alpha Zoo 因子的回测框架：Graph 是内建策略，不再是框架特例。
- 支持策略目录搜索、按 zoo 筛选、多选与全选。
- 支持异步批次回测；一个批次内每个策略拥有独立运行目录和报告。
- 在 StockPred 主页面展示批次与每份报告的摘要，支持多指标排序并可进入报告详情。
- 保存不可变策略源码快照、策略版本、数据快照和执行配置，以便因子代码后续变更后仍可复核历史结果。
- 保留现有 Graph CLI/API 的兼容入口。

不在首期范围内：跨不同批次且不同数据或执行配置的强行排名、实时交易、自动调参、对当前 StockPred 数据契约缺失字段的补数或静默降级。

## 第一性原理与约束

1. 策略之间只有在完全相同的数据快照、股票池、调仓频率、持有期、资金、费用和容量约束下，绩效指标才可以横向比较。
2. 因子标识不是版本标识。因子公式、实现代码或依赖的公共运算函数改变后，同一 ID 的计算结果可能变化，因此每次运行必须冻结实际执行的代码。
3. 单个因子不兼容或失败不能使数百个因子的批次整体丢失；每个子报告必须独立可审计。
4. StockPred 数据访问必须继续通过已有版本固定的只读数据网关，禁止为因子回测引入未固定的外部数据源。
5. 所有策略必须使用同一份组合执行和绩效计算逻辑；收益、夏普、回撤和交易指标必须来自费用后的净值与成交记录。

## 总体架构

```text
策略目录（Graph + Alpha Zoo Registry）
                 |
                 v
统一策略适配层：strategy_id -> 每个评价日的 ts_code -> score
                 |
                 v
统一 StockPred 回测引擎
  固定快照 / 股票池 / 选股 / 调仓 / 成交 / 净值 / 绩效
                 |
        +--------+--------+
        |                 |
        v                 v
单策略 run/report      批次摘要与排行榜
不可变代码快照          comparison_key
```

### 策略接口

策略适配层提供统一、最小的评分接口。公共回测引擎不关心策略来自 Graph 还是 Alpha Zoo，只接收一个评价日、固定的可交易股票池和足够的历史数据，然后返回按证券代码索引的截面分数及诊断信息。

- `GraphStrategy`：包装现有 Graph 信号服务，保留其风险与信号诊断。
- `AlphaZooStrategy`：通过 Alpha Zoo `Registry` 解析指定因子，在 StockPred 构建的面板上计算因子分数。
- 每个策略声明所需字段；面板缺失字段、空信号、或无法满足有效评价日比例时，形成有稳定错误码的子报告状态，不以零或未来数据代替。

现有 Graph 专用公开入口将保留，并在内部创建仅含 `stockpred_graph` 的统一批次，以保证既有 CLI、API、书签和测试调用不失效。

### StockPred Alpha Zoo 面板

每个评价日从固定的 StockPred 快照和点时可见股票池构造复权 OHLCV、成交额和可由当前数据契约确定性派生的字段。面板只能使用截至该评价日可见的数据。因子所需的字段由适配器预先校验，确保没有前视偏差和静默数据填充。

## 批次、报告与比较

### 批次模型

创建批次时，用户提交日期范围、研究参数与策略选择：显式 `strategy_ids` 或 `select_all=true`。服务先解析策略目录、固定一次数据快照并生成统一执行配置；由两者产生 `comparison_key`。

批次包含：

- `batch_id`、创建时间、提交选择、共享数据快照、共享执行配置和 `comparison_key`；
- 全局进度：策略总数、完成数、当前策略、成功/失败/跳过数；
- 所有子报告的摘要索引，且不复制子报告的完整工件；
- 仅同一 `comparison_key` 的子报告形成严格可比排行榜。

批次执行采用受限并发，避免全选数百因子导致内存、磁盘或数据读取失控。一个因子失败不会中断其余因子。

### 子报告模型

每个策略创建自己的 `run_id` 和标准运行目录，工件包括：

- `metrics.csv`、`equity.csv`、`positions.csv`、`trades.csv`、`symbol_metrics.csv`；
- 选中信号、评分信号和供图表展示的 OHLCV；
- 标准 `run_card`、请求上下文、运行状态和数据快照；
- 策略快照和版本信息；
- Graph 策略额外保存既有的 Graph 信号诊断。

报告概要至少包含策略名称、策略 ID、类型、zoo、策略版本、批次 ID、运行状态、回测区间、扣费后年化夏普、年化收益、最大回撤、胜率、换手率、报告链接以及失败/跳过原因。

### 排名指标

主页面默认按扣费后年化夏普比率降序排列。用户可按以下指标升降序排序：年化夏普、年化收益、最大回撤、胜率、换手率和状态/策略名称。指标均源于同一份费用后净值和交易记录；无有效值的失败或跳过报告保留在表中，不参与数值排名。

## 策略版本与可追溯性

每份子报告必须保存不可变 `strategy_snapshot`，其内容至少包括：

- 逻辑策略 ID、显示名称、类型、所属 zoo、公式与注册元数据；
- 当前策略实现和参与运算的共享代码的文件清单及每个文件的 SHA-256；
- 归档的实际源码副本（策略源码与影响其结果的公共运算/执行源码）；
- `strategy_version`：对规范化策略元数据和源码清单计算的 SHA-256；
- Git 提交号、工作区是否干净及必要的差异标识；
- Python 版本和已安装依赖的锁定信息；
- 固定数据快照标识和执行配置哈希。

历史报告以其目录中的源码归档和哈希为准。以后修改因子或 Graph 实现时，新的运行会得到新的 `strategy_version`；既有报告的显示、下载、审计和结果不会被改写。主页面和报告页均展示策略 ID 与短版本号，详情页可查看完整快照与源码归档信息。

## 页面与交互

### StockPred 主页面

主页面保留数据状态，并增加策略批次回测区域：

1. 策略目录支持全文搜索、按 zoo 筛选、多选与全选；Graph 作为内建策略显示。
2. 用户配置日期与统一执行参数后提交批次。
3. 执行中显示单调进度、当前策略和失败/跳过数量。
4. 批次总览表展示每个因子的报告摘要，默认按扣费后年化夏普降序，表头可切换排序指标。
5. 每行的报告链接打开 `/runs/{run_id}`；失败和跳过项显示具体原因而不是隐藏。

### 单策略报告页

沿用现有运行详情页，并增加策略快照卡片：策略名称、ID、类型、zoo、版本哈希、源码快照、Git 信息、数据快照和统一执行参数。报告主体展示总体指标、净值、交易、持仓、个股指标和个股 K 线/交易标记。Graph 策略保留其特有信号诊断标签；其他因子不显示空的 Graph 诊断。

## API 与兼容性

新增以批次为中心的接口：

- 获取统一策略目录；
- 创建 Alpha Zoo/Graph 策略批次；
- 查询批次状态和摘要排行榜；
- 订阅批次 SSE 进度；
- 获取报告详情仍使用现有通用运行详情接口。

保留 `/stockpred/graph/*` 的公开契约与响应形状。实现内部通过单策略 Graph 批次适配，但不要求现有用户迁移。

## 错误处理

- 无效策略 ID、空选择、无可选策略：请求校验失败。
- 因子输入字段缺失、空信号、无有效评价日、策略执行异常：只影响对应子报告，并存储稳定错误码和原因。
- 数据快照、策略版本或工件不完整：该报告标记失败或不可比较，绝不进入严格排行榜。
- 不同 `comparison_key` 的历史报告：可以浏览，但必须明确标示为不可直接横向比较。

## 验收与测试

1. 策略目录包含 Graph 和全部 Alpha Zoo 注册策略，并支持多选/全选。
2. Graph 与至少两个 Alpha Zoo 因子可通过同一回测引擎产生独立报告。
3. 同批次报告共享数据快照和执行配置，摘要默认按费用后年化夏普排序。
4. 单个因子失败不影响其他因子完成，主页面保留失败原因。
5. 每个报告保存可校验的策略源码快照和 `strategy_version`；修改策略实现后，新旧运行版本不同且旧报告内容不变。
6. 主页面可按指定指标排序并能进入对应的报告详情；详情页展示总体与个股信息。
7. Graph 原有 CLI/API/报告兼容测试继续通过。
8. 覆盖策略适配、前视偏差防护、批次服务、工件、版本快照、API/SSE、前端选择/排序/跳转以及兼容性测试。
