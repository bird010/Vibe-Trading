# StockPred 未完成批量回测展示设计

## 目标

在 StockPred 页面初始化时，展示所有持久化但未完成的策略批量回测及其中已经产生的报告结果；不续跑任务，也不改写已有批次文件。

## 现状与原因

批次的 `state.json` 与 `reports.json` 已在服务端持久化。前端只在用户刚创建批次时将其 `batch_id` 保存在组件状态中，刷新页面或服务中断后没有批次列表接口可重新加载这些数据。

## 方案

后端在现有策略批次路由下增加只读列表接口。该接口遍历 `strategy_batches` 目录，对状态为 `queued` 或 `running` 的批次调用既有摘要逻辑，返回批次状态、时间与策略报告列表。

前端增加对应 API 类型与请求，并在 StockPred 页面初始加载期间请求该列表。页面在“策略批量回测”区域展示每个未完成批次：批次标识、状态、成功/失败/排队数量，以及已经持久化的策略报告行。含 `run_id` 的策略报告保持现有链接行为。

## 非目标

- 不恢复、重启或取消任何批量任务。
- 不将遗留 `running` 状态改写为 `interrupted`。
- 不展示已完成批次历史。
- 不改变批量回测执行、报告排序或单策略报告格式。

## 错误处理

列表接口遇到缺失或损坏的批次目录时跳过该目录，避免单个历史批次阻塞页面。前端列表请求失败时保留现有页面功能，并不妨碍新批次创建。

## 验证

后端测试覆盖：仅返回 `queued`/`running` 批次，且结果包含已成功、失败、排队的报告行。前端测试覆盖：页面首次加载后渲染未完成批次及其策略状态。
