# 基金轮动批次与 K 线证据 UI 调整设计

## 目标

调整基金轮动批次页面的布局与 K 线交易标记表现：避免长策略名称和变体标签挤压批次区域；将历史批次放到原批次进度栏；在单次回测 K 线证据中区分权重未变时的仓位微调与目标权重变化的大笔买卖。

## 现状与约束

- `FundRotationTab` 当前为三栏布局：策略批次配置、批次进度、策略比较。
- 历史批次当前位于策略批次配置栏底部，批次进度栏展示当前批次状态、取消按钮和事件流。
- `StrategyVariantsEditor` 将策略选择框、变体标签、复制和删除按钮放在同一行；策略名称较长时会压缩后续控件。
- `TradeMarkersChart` 将交易记录转换为共享 `CandlestickChart` 的 B/S 标记。
- 交易记录和信号记录都可能包含 `target_weight`，但共享图表不应了解基金轮动领域的权重比较规则。
- 首次出现、缺少可比较的上一目标权重时，不应误判为“权重不变”。

## 设计

### 批次布局

1. 从策略批次配置栏移除历史批次列表。
2. 将原批次进度栏改为历史批次栏，保留三栏网格结构，标题改为“历史批次”。
3. 历史批次栏复用现有 `batches`、`activeBatchId`、`selectBatch` 和状态标签；无历史批次时显示“暂无批次”。
4. 移除该栏中的实时阶段图标、事件流和取消按钮。批次状态及阶段继续显示在历史批次每一行，当前批次仍可通过选中状态识别。
5. 调整变体编辑器首行的 flex 约束：策略选择框允许收缩并截断，变体标签保持有限宽度且允许收缩，操作按钮不被长文本挤出。该调整只针对布局，不改变表单数据和提交协议。

### K 线 B/S 标记

1. 在 `TradeMarkersChart` 中对单个标的的 signals 和 trades 按日期形成目标权重时间线。
2. 对每笔交易读取当前目标权重：优先使用交易自身的 `target_weight`；若交易没有该字段，则不能建立当前权重比较，保持当前样式。
3. 查找当前交易之前最近一次可用目标权重，来源包括此前的 signal 或带有目标权重的 trade。只有存在上一值且数值相等时，将该交易标记标记为 `muted`。
4. 首次目标权重、目标权重变化、缺少任一目标权重，以及阻断/拒绝/部分成交标记均不改变现有语义；浅色只改变正常 B/S 标记的视觉强度。
5. 扩展通用 `TradeMarker` 类型增加可选 `muted` 属性。`CandlestickChart` 在正常 B/S 标记上根据 `muted` 使用浅色/低透明度版本；拒绝、部分成交、延迟等现有状态优先级保持不变。

## 数据流

```text
signals + trades
      ↓
TradeMarkersChart：按时间计算 previous target weight
      ↓
SharedTradeMarker { side, status, muted }
      ↓
CandlestickChart：仅负责根据 muted 渲染浅色 B/S
```

## 测试与验收

- `FundRotationTab` 测试确认中栏显示“历史批次”、无批次时显示空态，且不再显示“批次进度”。
- `StrategyVariantsEditor` 测试覆盖长策略名称场景下的收缩布局 class/结构不回归。
- `TradeMarkersChart` 测试覆盖：权重未变生成 `muted: true`；权重变化、首次记录、缺少目标权重保持非 muted。
- `CandlestickChart` 测试或现有图表配置断言确认 muted 正常 B/S 使用浅色，而拒绝/部分成交仍使用原有状态样式。
- 运行相关 Vitest 测试与 TypeScript/Vite 构建，确认无回归。

## 非目标

- 不修改批次 API、SSE、历史批次数据结构或后台任务行为。
- 不改变目标权重计算、成交执行和 K 线数据范围。
- 不重新设计策略比较栏或其他回测图表。
