## 执行约束

- 仅实现 `RESEARCH_ONLY`。
- 保留工作区中 `correlation.py`、`pipeline.py` 的既有未提交改动，不得回退或覆盖。

- 修改 agent 负责代码和测试；review agent 独立按设计文档逐项验收，不直接修改代码。

## 修复任务

### 1. 建立设计符合性矩阵并复现缺陷

- 对设计文档各节建立“要求—实现位置—测试—结论”矩阵。
- 首先覆盖：状态机顺序、通用引擎迁移、残单重试、复权股数、共同缩放、ADV、诊断产物、基准、快照/manifest、前端六页签与 K 线买卖验证。
- 验证：每个已确认缺陷至少有一个修复前失败的测试或明确的静态证据。

### 2. 修复通用引擎与 ETF 执行语义

- 删除运行时双模式和旧方向接口，迁移 ChinaAEngine、CompositeEngine 及全部调用方到目标权重输入。
- 保持原有单品种策略行为一致；支持 ETF 专用费用、100 份交易单位、涨跌停/停牌、卖后买、共同缩放、最低佣金与现金非负。
- 修复冻结持仓对象写入、TradeRecord 构造和多资产同 bar 顺序依赖。
- 验证：新接口单元测试、旧调用方回归、多资产顺序置换测试、现金/费用边界测试全部通过。

### 3. 修复基金轮动日级执行闭环

- 按日推进账户；周频目标在下一可交易日开盘执行。
- 残单按原始差额逐日重试，直到成交、目标替换或因规则取消。
- 使用 `fund_adj` 处理份额连续性；缺失覆盖按设计排除或终止，并输出原因。
- ADV20 只使用执行日前数据；不足最小观察数时不得当作无限容量。
- 验证：时间边界、残单、复权、ADV、部分成交、现金不足与共同缩放测试通过。

### 4. 修复研究结果、基准和持久化

- 510300 与动态等权基准使用相同账户、执行日、费用、交易单位、滑点和容量规则；共同覆盖不足时明确失败。
- `orders.csv`、`trade_events.csv`、持仓、净值、诊断字段完整且状态一致。
- manifest 汇集不可变 Lance 版本和数据统计，并在其他产物成功后只写一次。
- 验证：端到端产物 schema、重放一致性、失败原子性和基准一致性测试通过。

### 5. 补齐前端研究闭环

- 保持独立于批量筛选的基金轮动交互。
- 补齐设计约定的六个页签/视图，包括持仓、交易验证、K 线买卖点和数据质量。
- K 线明确显示买卖时点、方向、价格、数量以及关联订单/成交状态。
- 验证：前端组件/API 测试及构建通过。

### 6. 独立审查与返修闭环

- review agent 逐项检查设计符合性、回归风险、前视偏差、执行会计和前后端契约。
- 每条发现记录严重级别、文件/行号、复现证据和期望行为。
- 修改 agent 逐条返修；同一 review agent 复审。循环直至无未解决发现。
